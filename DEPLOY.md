# Развёртывание «Дари Уют»

Сайт целиком поднимается через Docker Compose: PostgreSQL, бэкенд (FastAPI),
фронтенд (Nuxt SSR), nginx (reverse-proxy + HTTPS) и certbot (сертификат
Let's Encrypt с автопродлением). Всё — на одном сервере, один домен.

- Сайт: `https://дари-уют.рф`
- Админка: `https://дари-уют.рф/admin`

---

## Часть 1. Что должен подготовить владелец (Алексей)

Это нужно сделать **до** передачи задачи исполнителю.

1. **Сервер (VPS).** Linux (Ubuntu 22.04+ подойдёт), публичный IP, минимум
   1 vCPU / 2 ГБ RAM. Открыты порты **80** и **443**.
2. **Домен.** `дари-уют.рф` уже есть. В DNS-панели регистратора создать записи,
   указывающие на IP сервера:
   - `A` для `дари-уют.рф` (в панели может отображаться как `@` или
     `xn----7sblr3bog2g.xn--p1ai`) → IP сервера
   - `A` для `www.дари-уют.рф` → тот же IP
   - Проверить (подождав распространения DNS, до ~1 часа):
     `dig +short xn----7sblr3bog2g.xn--p1ai` — должен вернуть IP сервера.
3. **Решить и передать исполнителю секреты** (см. таблицу ниже) — либо
   заполнить `.env` самому и передать его исполнителю безопасным каналом.

### Значения для `.env` (передать исполнителю)

| Переменная | Что это | Кто задаёт |
|---|---|---|
| `SITE_URL` | `https://дари-уют.рф` — оставить как есть | — |
| `POSTGRES_PASSWORD` | пароль БД, случайная строка | сгенерировать: `openssl rand -hex 24` |
| `SECRET_KEY` | ключ подписи JWT/сессий | сгенерировать: `openssl rand -hex 32` |
| `FIRST_ADMIN_EMAIL` | логин в админку | ваш выбор, напр. `admin@dari-yut.ru` |
| `FIRST_ADMIN_PASSWORD` | пароль в админку | придумать надёжный |
| `FIRST_ADMIN_NAME` | имя администратора | напр. `Администратор` |
| `CERTBOT_EMAIL` | e-mail для Let's Encrypt (уведомления) | ваш e-mail |

> Логин и пароль администратора (`FIRST_ADMIN_*`) — это доступ к
> `https://дари-уют.рф/admin`. Сохраните их.

## Часть 2. Что делает исполнитель на сервере

Предполагается свежий Linux-сервер с root/sudo.

### 1. Установить Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # затем перелогиниться
```

Проверка: `docker compose version` — должно вывести версию.

### 2. Получить код и настроить `.env`

```bash
git clone <ССЫЛКА_НА_РЕПОЗИТОРИЙ> dari-yut
cd dari-yut
cp .env.example .env
nano .env          # заполнить значениями из таблицы выше
```

### 3. Запустить (одна команда)

```bash
chmod +x init-letsencrypt.sh
./init-letsencrypt.sh
```

Скрипт соберёт образы, поднимет все сервисы, выпустит настоящий
TLS-сертификат Let's Encrypt и перезагрузит nginx. В конце выведет ссылки на
сайт и админку.

> ⚠️ Запускать `init-letsencrypt.sh` нужно **только при первом развёртывании**.
> Для перезапусков и обновлений используется обычный `docker compose` (ниже).

### 4. Проверить

- `https://дари-уют.рф` — открывается сайт с валидным сертификатом.
- `https://дари-уют.рф/admin` — вход по `FIRST_ADMIN_EMAIL` / `FIRST_ADMIN_PASSWORD`.
- Форма «Запросить опт-прайс» на сайте отправляется без ошибок.

## Эксплуатация

```bash
# Логи
docker compose logs -f            # все сервисы
docker compose logs -f backend    # только бэкенд

# Обновление после git pull
git pull
docker compose up -d --build

# Перезапуск / остановка
docker compose restart
docker compose down               # остановить (данные БД и медиа сохранятся в томах)
```

- **Данные** (БД, загруженные изображения, сертификаты) лежат в docker-томах
  `pgdata`, `media`, `certbot-conf` и переживают перезапуск/пересборку.
- **Миграции БД** и создание первого админа выполняются автоматически при
  старте бэкенда.
- **Продление сертификата** — автоматически, сервисом `certbot` (проверка
  каждые 12 часов).

## Если что-то не работает

| Симптом | Причина / решение |
|---|---|
| `init-letsencrypt.sh`: ошибка выпуска сертификата | DNS ещё не указывает на сервер, или порт 80 закрыт фаерволом. Проверьте `dig` и доступность `http://<IP>`. |
| nginx не стартует, «cannot load certificate» | Сертификата нет — запускать только через `init-letsencrypt.sh`, не через голый `docker compose up`. |
| 502 Bad Gateway | Бэкенд/фронт ещё поднимаются или упали: `docker compose logs -f backend frontend`. |
| Не заходит в админку | Проверьте `FIRST_ADMIN_EMAIL`/`FIRST_ADMIN_PASSWORD` в `.env`; админ создаётся при первом старте бэкенда. |
